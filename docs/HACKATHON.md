# FortyGuard Hackathon'26 delivery contract

Official email/Slack guidance reviewed through **27 Aug 2026 (Day 8)** gives the following judging weights:

- Impact & Relevance — 40%
- Technical Execution — 35%
- Innovation — 15%
- Communication — 10%

Submission deadline: **30 Aug 2026, 11:59 PM GST**.

Required final deliverables:

1. official submission form;
2. live demo URL that opens in a private/incognito browser without login or installation;
3. demo video no longer than 3 minutes showing the project actually working, with clear voiceover;
4. GitHub/GitLab repository with reproducible setup and no exposed API key.

The product should solve a genuine urban-heat problem for a real user/client, make FortyGuard temperature intelligence central rather than decorative, be client-grade/deployable, and communicate measurable value clearly.

SAM-WM therefore optimizes one defensible workflow:

1. acquire real FortyGuard thermal evidence;
2. preserve request/activity/hash provenance;
3. forecast thermal dynamics with a frozen trained SAM-WM checkpoint when compatible context exists;
4. expose uncertainty and OOD evidence;
5. use CANDRA to ask whether a physical intervention has sufficient independent causal evidence;
6. abstain when an intervention effect is not identified;
7. visualize OBSERVED / REAL REPLAY / PREDICTED states distinctly in the 3D UI.

The software is a decision/intelligence layer. Physical interventions cool the real environment; the software itself does not directly lower temperature.
